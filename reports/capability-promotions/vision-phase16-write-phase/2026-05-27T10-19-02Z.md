## 1. State file path

`data/capability-certifications.json` (default).

Overridable via `CRUCIBLE_CAPABILITY_STATE_DIR` env var — tests
point this to a tmp dir so they never contaminate the real
`data/` directory.

Schema: `crucible.capability-certifications.v1`. Body shape (when
Vision is promoted):

```jsonc
{
  "schema": "crucible.capability-certifications.v1",
  "capabilities": {
    "vision": {
      "tier": "CAPABILITY_CERTIFIED",
      "promoted": true,
      "promotedAt": "<ISO timestamp>",
      "promotedBy": "<operator>",
      "promotionReceipt": "<absolute path to receipt JSON>",
      "operatorNote": "<optional operator note or null>",
      "evidence": {
        "aggregateDecision": <CapabilityPromotionDecision>,
        "qualifyingFamilies": ["Anthropic", "GPT-5", "MiMo"],
        "qualifyingRoutes": [
          { "provider": "openrouter", "model": "xiaomi/mimo-v2.5",            "family": "MiMo" },
          { "provider": "openai",     "model": "gpt-5.4-mini",                "family": "GPT-5" },
          { "provider": "openrouter", "model": "anthropic/claude-haiku-4-5",  "family": "Anthropic" }
        ],
        "sourceReports": [<CapabilityEvidenceRef>...],
        "suiteSize": 15,
        "repeatRuns": 3,
        "stablePassRate": <0..1>
      },
      "affectsLeaderboard": false,
      "affectsCertification": false
    }
  }
}
```

Default at fresh checkout: no state file → Vision remains
EXPERIMENTAL → UI shows the existing EXPERIMENTAL chip. The
`data/capability-certifications.json` path is gitignored — it is
operator-written state, not source. Promotion **receipts** at
`reports/capability-promotions/vision/` ARE committed to the repo
(immutable audit evidence, same convention as other reports).

## 2. Write endpoint path

`POST /api/capabilities/vision/promote`.

Registered GET-not-allowed (P21 asserts GET → 404). PUT/PATCH/DELETE
also 404 (P22 asserts none mutate state).

## 3. Confirmation phrase

```
PROMOTE_VISION_CAPABILITY_CERTIFIED
```

Required in the request body's `confirm` field. Missing or wrong
phrase → 400, no write (P2, P3).

## 4. Whether promotion was executed

**No.** Phase 16 implemented the endpoint but did not invoke a real
production promotion. The write requires explicit operator
intent — automating it would defeat the doctrine guarantee that
capability promotion is operator-attested.

If you want to promote now, run (with `npm run serve` listening on
`127.0.0.1:18795`):

```bash
curl -X POST http://127.0.0.1:18795/api/capabilities/vision/promote \
  -H 'Content-Type: application/json' \
  -d '{"confirm":"PROMOTE_VISION_CAPABILITY_CERTIFIED",
       "operatorNote":"Promoting Vision after Phase 15 aggregate dry-run eligibility (3/3 families: MiMo + GPT-5 + Anthropic; 0 blocking reasons).",
       "operator":"<your-name>"}'
```

Successful response shape:

```jsonc
{
  "ok": true,
  "capability": "vision",
  "promoted": true,
  "previousTier": "EXPERIMENTAL",
  "promotedTier": "CAPABILITY_CERTIFIED",
  "receiptPath": "<absolute path to receipt JSON>",
  "receiptMarkdownPath": "<absolute path to receipt MD>",
  "statePath": "<absolute path to data/capability-certifications.json>",
  "affectsLeaderboard": false,
  "affectsCertification": false,
  "certifiedModelsJsonUntouched": true
}
```

If the current aggregate is not eligible (evidence dropped,
recurring CONFIG/PROVIDER/FIXTURE/SCORER appeared, etc.) → 422,
no write (P23). If the confirmation phrase is missing/wrong → 400,
no write (P2, P3).

## 5. Receipt path

`reports/capability-promotions/vision/<ts>.json` +
`reports/capability-promotions/vision/<ts>.md`.

Overridable via `CRUCIBLE_CAPABILITY_REPORTS_DIR` env var (tests
use tmp dirs).

### Receipt JSON shape

Schema `crucible.capability-promotion-receipt.v1`. Fields include:
`capability`, `previousTier`, `promotedTier`, `aggregateDecision`
(the full `CapabilityPromotionDecision` payload at promotion time),
`qualifyingFamilies` (sorted), `qualifyingRoutes` (with families),
`sourceReports` (`CapabilityEvidenceRef[]` from each qualifying
route's stability evidence), `suiteSize`, `repeatRuns`,
`stablePassRate`, `recurringAttributions`,
`certifiedModelsJsonSha256Before`,
`certifiedModelsJsonSha256After` (must be byte-identical to
`Before`), `modelCertificationTierMutated` (literal `false`),
`operator`, `operatorNote`, `generatedAt`. The literal-false
`affectsLeaderboard` and `affectsCertification` flags are doctrine
guarantees — non-negotiable per call.

### Receipt Markdown shape

Human-readable rendering of the same data, with explicit doctrine
guarantees enumerated at the bottom:

- This promotion writes only `data/capability-certifications.json`
  (capability-certifications state) and this receipt.
- `certified-models.json` was NOT mutated (sha256 BEFORE === sha256
  AFTER; both should match).
- `MODEL_CERTIFICATION.models[].tier` was NOT mutated.
- Vision is NOT added to the leaderboard composite.
- Vision is NOT added to the general model certification.
- The receipt is immutable; future re-promotions write new
  receipts, this file is never edited.
