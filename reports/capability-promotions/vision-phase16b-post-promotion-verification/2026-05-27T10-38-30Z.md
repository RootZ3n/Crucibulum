## 4. Restart hygiene fix

### Diagnosed bug

The pre-existing `~/.bashrc` alias was:

```bash
alias crux-restart='sudo systemctl restart crucible && echo "Crucible restarted"'
```

This printed "Crucible restarted" whenever `systemctl restart`
exited 0, which is insufficient for several operationally
real failure modes:

- **port-collision case** — a manually-started `npm run serve`
  process holds `:18795`, so the systemd-managed restart starts a
  new process that fails to bind the port. The old (manual)
  process keeps serving; `systemctl restart` still exits 0.
- **silent-crash case** — the new systemd-managed process starts
  but crashes before binding the port. `systemctl restart` exits
  before the crash is detected and reports success.
- **same-PID stale-cache case** — port held by something the unit
  doesn't actually manage; nothing changes on the wire but
  `systemctl restart` still exits 0.

### Fix

New `scripts/crux-restart.sh` — verification-gated restart that
prints "Crucible restarted" only when **all three** of the
following hold:

1. A process is bound on `:18795` after the restart.
2. The bound PID is different from the pre-restart PID.
3. `/api/health` uptime has dropped below 15s (proves it's a
   freshly-started process, not a stale one cached behind a
   reverse proxy).

Exit codes communicate the specific failure:

- `0` — success (all three verifications passed)
- `2` — `systemctl restart` returned non-zero (restart aborted)
- `3` — no process listening on `:18795` after restart (port unbound)
- `4` — PID did not change (stale process — usually a manual
  `npm run serve` is holding the port)
- `5` — `/api/health` uptime did not reset (caching / wrong
  process)

Polling cadence: 20 attempts at 0.5s intervals (~10s total) for
the new process to come up and pass all three checks.

### `~/.bashrc` updated

The duplicate `crux-restart` alias definitions (formerly at lines
~240 and ~268) both now invoke the new script:

```bash
alias crux-restart='bash /mnt/ai/crucible/scripts/crux-restart.sh'
```

Each occurrence carries a Phase 16-B header comment pointing at
the script. The `~/.bashrc` lives outside the repo and is not
under source control here, but the change is recorded in this
report so a future operator can recreate it.

### Verification

The script has been syntax-checked (`bash -n`) and reviewed by
hand. The actual restart was deliberately NOT triggered as part
of writing this report (would interrupt the live API serving
`promoted: true`); the script will run as designed on the next
operator-initiated `crux-restart`. Expected output on success
(observed from the script's design):

```
→ pre-restart on :18795: pid=<old-pid> uptime=<n>s
→ post-restart on :18795: pid=<new-pid> uptime=<m>s
✓ Crucible restarted on :18795 (pid <old> → <new>; uptime <n>s → <m>s)
```

On the port-collision failure mode (manual `npm run serve`
holding the port), the script will exit 4 with:

```
✗ PID did not change (still <pid>) — systemctl reported success but a stale process is still serving
  (the systemd unit may not own this port; check with: ss -tlnp | grep :18795)
```
