## Before-issue summary

The previous Luna pass + layout correction gave Crucible the right
visual language and the right desktop topology, but the **product flow
was still wrong**:

- The leaderboard — which IS Crucible's product (which model is winning) —
  sat halfway down the page inside the Active Arena. The operator had
  to scroll past run controls / vitals / welcome text to reach the
  ranking. The simple welcome card and the recommendations sidebar
  beat the leaderboard to the eye.
- The lane `renderLaneCommandTop` "Command Deck" panel split its body
  into a `.dual-grid` (50/50 columns). At desktop widths this was
  fine; at the new 3-column command-deck shell the inner right column
  (Adapter · Provider · Cert banner · Model select · Run controls)
  was crushed into ~280 px. Long model ids (`google/gemini-3.1-flash-lite`,
  `claude-haiku-4-5-20251001`) clipped, the multi-select was 6 rows
  tall and unreadable, and the action buttons were 2-up tiny squares
  on the right edge.
- The "Provider Health Bars" / "Provider Health Overview" labels read
  as analytics, not as the canonical leaderboard. There was no top-of-
  page chip stating "#1 model right now".

## Layout changes made

### 1 · New top-of-page Ranking Deck (`renderRankingDeck`)

A full-width deck-window mounted between the global banners and the
deck grid. Always shows the current lane's top 3 models as champion
cards (#1 highlighted with cyan glow + crown chip), with:

- model id (wraps via `overflow-wrap:anywhere`)
- trial count + source provider
- composite score with pass / warn / fail border
- "Open Full Leaderboard" affordance that scrolls to the existing
  in-arena comparison chart

The deck header shows the lane scope label and sample size so the
operator never has to guess which lane the ranks belong to. A
PROVISIONAL chip appears when `<3` runs are in scope.

Clicking a rank card calls `focusModelDrilldown(tabKey, modelId)` —
the same drilldown the leaderboard rows below the fold already use.

### 2 · Restacked Active Arena command card (`renderLaneCommandTop`)

The `.dual-grid` split was replaced with a vertical `.command-card-stack`:

```
┌────────────────────────────────────────┐
│ Tests picker  (full width)             │
├────────────────────────────────────────┤
│ Adapter | Provider  (full width grid)  │  ← auto-fit, 220px min
├────────────────────────────────────────┤
│ Certification banner                   │
├────────────────────────────────────────┤
│ MODELS · N ARMED                       │
│ ┌──────────────────────────────────┐   │
│ │ multi-select, 100% width,        │   │  ← wraps long ids
│ │ 200-340px tall, mono             │   │
│ └──────────────────────────────────┘   │
├────────────────────────────────────────┤
│ Run count picker                       │
├────────────────────────────────────────┤
│ Action grid (centered, auto-fit):      │
│ [▶ RUN BENCHMARK ] [▶▶ RUN ALL ]       │  ← span 2 each
│ [LOCAL] [CLOUD] [↻ REFRESH]            │
└────────────────────────────────────────┘
```

`.command-card{overflow:visible}` prevents any inner element from
being clipped by the card itself. The model select uses
`width:100%; min-height:200px; max-height:340px` and its options use
`white-space:normal` so long ids wrap inside the dropdown view.

### 3 · Wrap-safe action grid

`.action-grid{display:grid; grid-template-columns:repeat(auto-fit,
minmax(180px,1fr))}` — buttons reflow at any width, never clip,
never crush. `.button.primary` spans 2 cells on wide layouts so the
two RUN actions pop visually; falls back to single span on phones.

## Remaining UI debt

- **Ranking deck "Open Full Leaderboard" smooth-scroll** lands on the
  in-arena `.comparison-chart` only when the active tab is
  dashboard / a lane that emits one. On `providers` the affordance
  becomes a no-op; would be nicer to disable it or jump to the
  provider matrix.
- **Champion crown chip** truncates at 28 chars to fit the deck header
  on narrow desktops. Long model ids show e.g. `xiaomi/mimo-v2-pro` but
  not the provider prefix. Acceptable tradeoff — the full id is on the
  card body below.
- **Three rank cards on tablet (1024 px)** sit tight at ~210 px each.
  Readable, but if a 4-word model label appears we'd want
  `grid-template-columns:repeat(auto-fit,minmax(220px,1fr))` instead of
  fixed `repeat(3,...)`. Left for a follow-up — current model ids fit.
- **Active Arena vitals still vertical** — the arena still renders the
  full `renderDashboard()` / `renderLane()` body below the command
  card. A future pass could move category-matrix / score-distribution
  into the bottom `.deck-floor` so the arena is purely operational
  (command card + recent runs + focused run). Out of scope for this
  pass; scope was leaderboard-first + clipping fixes.
