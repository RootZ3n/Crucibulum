# Crucible — side-rail detail decks + uncapped rails

- **Timestamp (UTC):** 2026-05-25T19-42-24Z
- **Operator:** Zen
- **Branch:** master
- **Predecessor pass:** `crucible-real-leaderboard-first/2026-05-25T19-13-27Z.md`

## What the operator asked for

Two related changes:

1. **Focused Run, Provenance, Best Model Recommendations, Methodology**
   should sit on the SIDE of the main scrolling window rather than be
   shoved down below run controls (where they force scrolling).
2. The four right-rail triage cards (**Failure Board, Provider Bay,
   Evidence Vault, Release Gate**) shouldn't require scrolling either —
   stretch the rail so they fit.

## What changed

### 1 · New side-rail detail decks

- `renderQuickPicksRailDeck(tabKey)` — Best Model Recommendations
  card. Mounted in the LEFT rail under Evaluation Rooms. Pulls from
  `reviewSummary(tabKey)` so it tracks whatever the hoisted
  leaderboard shows.
- `renderFocusedRunRailDeck(tabKey)` — Focused Run detail panel
  wrapped in a deck-window. Mounted in the RIGHT rail after the
  four triage decks. Because `renderFocusedRun` already includes
  the **Provenance** ("Bundle Trace") and **Methodology** ("Judge
  Stack") subpanels, both ride along into the rail automatically.

The arena center column no longer renders either of these — the
`renderFocusedRun` calls in `renderDashboard` and `renderLane` were
removed, and the inline Quick Picks `winner-stack` was stripped from
the dashboard side column.

### 2 · Leaderboard moved INTO the center column

Previously the full leaderboard zone was emitted ABOVE
`<main class="deck-grid">` as a full-width banner. At 1920×1080 the
leaderboard + champion strip + 7 ranked rows was tall enough that the
rails below it sat under the fold — operator had to scroll past the
leaderboard to see the side cards.

Fix: the leaderboard zone now mounts INSIDE `deck-rail-center`,
immediately above the arena shell. Result on desktop:

```
┌── deck-grid ─────────────────────────────────────────┐
│  LEFT       CENTER                          RIGHT    │
│  Rooms      ┌── leaderboard zone ──┐        Failure  │
│  Best       │ champion strip       │        Board    │
│  Models     │ ranked rows table    │        Provider │
│             └──────────────────────┘        Bay      │
│             ┌── arena shell ───────┐        Evidence │
│             │ run controls         │        Vault    │
│             │ vitals, run history  │        Release  │
│             └──────────────────────┘        Gate     │
│                                             Focused  │
│                                             Run      │
│  ┌────────── deck-floor ────────────────────────────┐ │
│  │ evidence feed                                    │ │
│  └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────-┘
```

All side cards visible at the same time as the leaderboard — no
scrolling past a full-width banner to reach them.

### 3 · Rails uncapped (no internal scrolling)

Previously the `@media (min-width:1200px)` block set
`position:sticky; top:72px; max-height:calc(100vh - 96px);
overflow-y:auto` on both rails. With Focused Run added to the right
rail and Quick Picks added to the left rail, the rail content
exceeded the viewport cap and forced internal scrolling.

Replaced with `position:static; max-height:none; overflow:visible;`
so the rails extend to their natural content height. The operator
now scrolls the PAGE (not the rail) to reach lower-rail decks, but
no rail content is hidden behind an internal scroll.

### 4 · CSS for rail-mounted Focused Run

The focused run panel has a model callout + signal cards grid +
operational glyph grid + provenance + methodology + test review
explorer — all rendered fine in a wide arena, but it would overflow
the narrower rail. New CSS collapses the inner grids to single column
inside `.focused-run-rail-body`, shrinks the score number, tightens
padding, and lets the rail's `overflow:visible` (via the uncapped
rule above) handle the height naturally.
