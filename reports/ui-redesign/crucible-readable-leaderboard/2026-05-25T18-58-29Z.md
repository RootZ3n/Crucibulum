## Before problem summary

Even after the leaderboard-first pass put the Ranking Deck above the
fold, the **secondary leaderboard sections inside the arena** were
still crushing model names:

- `.comparison-row` (the main leaderboard rendered by
  `renderComparisonBars`) had `grid-template-columns:minmax(0,1.1fr)
  minmax(120px,2fr) 56px minmax(80px,.8fr)`. With `minmax(0, …)` the
  model column could collapse to **zero** when the score bar wanted
  more room.
- `.ranked-row` (Ranked Model Comparison) had
  `minmax(0,1.2fr)` for the model column — same collapse.
- `.leader-strip` had `minmax(0,1fr)` model column.
- `.comparison-model`, `.ranked-model`, `.ls-model` all forced
  `white-space:nowrap; overflow:hidden; text-overflow:ellipsis`,
  so the operator saw `deepseek/de…`, `xiaomi/mimo…`,
  `google/gemi…` with no way to tell which model was which.
- Top `Quick Picks` `winner-row` didn't carry a `title=` attr, so
  even the tooltip couldn't disambiguate a shortened name.
- `.rank-cards` (top Ranking Deck) used `repeat(3,minmax(0,1fr))` —
  a fixed 3-up grid that crushed cards at narrow widths instead of
  wrapping to 2-up.
- `.stage-grid` (dashboard 2-col) gave the side column too much
  weight (`minmax(280px,.5fr)`), stealing width the leaderboard
  needed for full names.

## What changed

### CSS — readable column widths + wrap allowed

| Selector | Before | After |
|----------|--------|-------|
| `.comparison-row` | `minmax(0,1.1fr) minmax(120px,2fr) 56px minmax(80px,.8fr)` | `minmax(260px,1.6fr) minmax(140px,2fr) 60px minmax(80px,1fr)` |
| `.ranked-row` | `32px minmax(0,1.2fr) minmax(100px,1.8fr) 50px minmax(60px,auto)` | `36px minmax(280px,1.6fr) minmax(140px,2fr) 56px minmax(60px,auto)` |
| `.leader-strip` | `24px minmax(0,1fr) minmax(60px,auto) 56px` | `28px minmax(220px,1.6fr) minmax(60px,auto) 60px` |
| `.rank-cards` | `repeat(3,minmax(0,1fr))` | `repeat(auto-fit,minmax(300px,1fr))` |
| `.stage-grid` | `minmax(0,1.4fr) minmax(280px,.5fr)` | `minmax(0,2fr) minmax(260px,.6fr)` |

### CSS — wrap instead of ellipsis on desktop

All three name cells (`.comparison-model`, `.ranked-model`, `.ls-model`)
now override the legacy ellipsis with:

```css
white-space:normal;
overflow:visible;
text-overflow:clip;
overflow-wrap:anywhere;
word-break:break-word;
line-height:1.3;
```

Long ids like `google/gemini-3.1-flash-lite` wrap to 2 lines (breaks
on the slash or hyphen) instead of collapsing to `google/gemi…`.

### CSS — category matrix first column wider + wrap

`.ranked-table th:first-child, td:first-child` → `min-width:240px;
max-width:360px; white-space:normal; overflow-wrap:anywhere;` so the
matrix can hold a full model id without horizontal scroll.

### CSS — phone (< 600 px) safe stacking

```css
.comparison-row{grid-template-columns:1fr; gap:10px; padding:12px}
.ranked-row{
  grid-template-columns:32px 1fr;
  grid-template-areas:
    "pos model"
    "bar bar"
    "score tags";
}
.leader-strip{grid-template-columns:28px 1fr auto}
```

Phone gets the model id on its own full-width row, with bar / score
below — no clipping, no horizontal scroll.

### JS — full id available via `title=` attr

Every place the renderers emit a leaderboard row now adds
`title="${esc(model)}"` so even a shortened cell can be hovered for
the full id:

- `<div class="comparison-model" title="...">` — both call sites
- `<div class="ranked-model" title="...">` — Ranked Model Comparison
- `<span class="winner-model" title="...">` — Quick Picks chips
- `<div class="winner-row" title="...">` — Quick Picks rows

## Remaining UI debt

- **Category matrix horizontal scroll on very narrow phones** — even
  with `min-width:240px` on the first column the matrix may need a
  horizontal scroll on 320 px phones if many columns are visible.
  Acceptable since the matrix is power-user content; logged.
- **Two-line wrap in Quick Picks** — fine for legibility but uses an
  extra row of vertical space. If a future pass moves Quick Picks to
  a horizontal strip the wrap budget would shrink; revisit then.

## Honesty preserved

- No leaderboard data was hidden. Every change widens the available
  room for the operator-relevant fields (model id, run count, pass
  rate, cost) without dropping any of them.
- `title=` attrs guarantee the FULL id is always available via
  hover, even on a viewport where wrap-to-2-lines isn't enough
  (e.g. legendary-long id with no break opportunities).
- Trust score, certification scope, PROVISIONAL chip, and the
  champion crown all stayed in place above the leaderboard.
