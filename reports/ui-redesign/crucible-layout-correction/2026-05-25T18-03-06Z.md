## What was wrong with the prior pass

The Luna-style **visuals** were correct (bevel windows, glowing plate
titles, neon chips, deck rails) but the **layout** was still mobile-column
thinking applied to desktop:

- `.app-shell.deck-shell{max-width:1720px}` — desktop content topped out
  far inside the viewport; a 1920 px monitor had ~200 px dead gutters
  on each side.
- The big `renderHero()` `.abyss-banner` was emitted inside the arena
  (`renderActiveArenaShell`) AND it was visually present, so the
  operator saw a giant "Crucible" trust-score card eating the center
  column above the run controls. Critical right-rail decks (Failure
  Board, Provider Bay, Evidence Vault, Release Gate) ended up below the
  fold because the arena was so tall.
- Right-rail `bay-row .bay-v` and chips used `white-space:nowrap`
  inherited from the global chip rule — long provider/model ids
  (`google/gemini-3.1-flash-lite`) clipped off the right edge.
- Verdict/mission banners rendered inside the arena, pushing the
  arena's first-fold content (chips, tests, controls) below the actual
  fold whenever a critical-failure stripe appeared.
- Rails were not sticky — scrolling the arena scrolled the rails away,
  so the operator could not glance at Failure Board while reviewing a
  trial.

## Layout changes made

### CSS — `ui/crucibulum.css`

- `.app-shell.deck-shell` now declares `width:min(96vw,1760px); max-width:none;`
  — content fills the desktop instead of leaving 200 px gutters.
- `.deck-rail-left` / `.deck-rail-right` become `position:sticky; top:72px;
  max-height:calc(100vh - 96px); overflow-y:auto;` at ≥ 1200 px so the
  triage rails stay anchored while the arena scrolls.
- Added `.arena-header-strip` — a tight per-tab strip that surfaces
  lane title + trust + pass + cert + model + provider, replacing the
  giant in-arena hero.
- `.arena-shell .deck-body > .abyss-banner{display:none}` suppresses
  the legacy hero inside the arena without removing the markup (test
  contract still passes).
- Text-clipping safety: `min-width:0` on all rail children;
  `overflow-wrap:anywhere` + `white-space:normal` on `.evidence-row .ev-v`,
  `.bay-row .bay-v`, `.gate-state`, `.room-name`, `.room-meta`,
  `.feed-model`, `.cmd-rail-chips .chip`, `.deck-subtitle`.
- New responsive cascade replacing the old single-step:
  - ≥ 1500 px: 3-col deck, rails sticky at ≥ 1200 px
  - 1200–1499 px: 3-col with tightened rail widths
  - 900–1199 px: 2-col `"center right" / "left right" / "floor floor"` — rails un-stick
  - 600–899 px: single column, rooms become horizontal pills
  - < 600 px: compact pills/cards, deck footer wraps

### JS — `ui/index.html`

- New `renderArenaHeaderStrip()` — compact 1-line lane summary using
  `statsForTab` + `selectedProviderModelSummary` + `laneScopeDescriptor`.
- `renderActiveArenaShell()` now mounts the compact strip + leaves
  `renderHero()` markup in the body (legacy contract) but the CSS hides
  it visually.
- `render()` hoists `renderVerdictBanner()` + `renderMissionBanner()`
  into a `<div class="deck-banners">` stripe between the cmd-rail and
  the deck-grid so they no longer eat the arena's first fold.

### Clipped-text fixes

| Element | Fix |
|--------|-----|
| `cmd-rail` chip stack (long PROVIDER · MODEL · CERT labels) | `white-space:normal; line-height:1.3` so the stack wraps to a second row instead of clipping |
| `bay-row .bay-v` (e.g. `google/gemini-3.1-flash-lite`) | `overflow-wrap:anywhere; word-break:break-word` |
| `evidence-row .ev-v` (bundle ids, hashes, target lists) | same wrap rules + text-align right |
| `room-card` body (multi-word room names) | `overflow-wrap:anywhere; white-space:normal; align-items:start` so the pill never crowds out the name |
| `feed-model` (model · task labels) | `overflow-wrap:anywhere; white-space:normal` |
| Right-rail / left-rail grid children | `min-width:0` so they can actually shrink under their content |

## Remaining UI debt

- **Arena content density** — the arena body still mounts the full
  `renderActiveTab()` output (vitals, leaderboard, score distribution,
  comparison bars, category review, focused run). That is a lot inside
  one column. A future pass could move the leaderboard / score
  distribution / category matrix into the `.deck-floor` bottom zone so
  the arena is purely operational (controls + recent trials + focused
  run). Doing it now would require refactoring `renderDashboard` /
  `renderLane`, which the layout-correction brief said to keep scoped.
- **Sticky-rail scrollbar look** — Firefox honors `scrollbar-width:thin`
  + `scrollbar-color`, WebKit gets a 6 px thumb. Edge cases (very tall
  rails, scrolling overshoot) may show a faint thumb only when the rail
  exceeds viewport height. Acceptable; logged.
- **Room cards on small desktop (≤ 1199 px)** — at the 1199 px
  breakpoint the left rail shares its row with the right rail, which
  can leave room cards a little tight. The 2-col layout was the right
  call (matches the spec) but a follow-up could let the rooms row
  expand to full width when the right rail is shorter.
