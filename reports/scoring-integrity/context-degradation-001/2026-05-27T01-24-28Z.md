## 1. Root cause of 43

The Hermes "impossible 43" reading came from interpreting
`score.total_percent` as the **per-question correctness** score
when it is actually the **lane composite** — a weighted blend of
correctness + efficiency:

```
combineConversationalScore(correctness, efficiency):
  if (correctness <= 0) return 0;
  return round((correctness * 0.85 + efficiency * 0.15) * 100) / 100;
```

For context-degradation-001 (3 binary `text_match_all` questions,
weight 3 each, total weight 9) the legal `correctness` values are:

```
0 of 3 → 0       1 of 3 → 1/3 ≈ 0.3333    2 of 3 → 2/3 ≈ 0.6667    3 of 3 → 1.0
```

These are exactly the {0, 33.33, 66.67, 100} buckets Hermes
correctly enumerated. **Combined with efficiency ≈ 1.0** (which
dominates all on-disk bundles because the prompts fit comfortably
under the time/token budget), the **composite total** becomes:

| Pass mix | `correctness` | `total` (composite) |
|---|---:|---:|
| 0 of 3 | 0.0000 | **0** (correctness gate forces 0) |
| 1 of 3 | 0.3333 | `0.3333*0.85 + 0.15 = 0.4333` → round → **0.43** |
| 2 of 3 | 0.6667 | `0.6667*0.85 + 0.15 = 0.7167` → round → **0.72** |
| 3 of 3 | 1.0000 | `1.0*0.85 + 0.15 = 1.0` → **1.00** |

The Crucible bundle stores both fields side-by-side on disk:

```json
"score": {
  "breakdown_percent": {
    "correctness": 33.33,   ← Hermes's enumeration was for THIS
    "efficiency": 100, "regression": 100, "integrity": 100
  },
  "total_percent": 43       ← Hermes was reading THIS
}
```

The two are different quantities with different (correctly-published)
formulas. Reading them as the same field is the source of the
"impossible" claim. The full per-bundle reconstruction is in the
sibling file
`reports/scoring-integrity/context-degradation-001/2026-05-27T01-24-28Z-score-reconstruction.md`.

The same composite (43) repeating across `deepseek-v4-pro`,
`deepseek-v4-flash`, `xiaomi/mimo-v2.5`, `xiaomi/mimo-v2-flash`,
`gemini-3.5-flash`, and `x-ai/grok-4.3` is the **expected**
deterministic output of a deterministic blender on the deterministic
"Q1 fail / Q2 pass / Q3 fail" failure mode that the test's
substring contract elicits from these models. The earlier bundles
showing 100 are the same models scoring 3-of-3 PASS on different
runs (the substring fragility points — literal `"two"` and
`"200 client"` — are paraphrase-sensitive).

## 3. Scoring invariant behaviour

`core/scoring-invariant.ts` exports:

- `isStrictlyBinaryConversationalManifest(questions)` — true only
  if every question is a binary scoring type
  (`text_match` / `text_match_all` / `regex_match` /
  `numeric_fact_match` / `recall` / `correction` / `proactive` /
  `hedge_count` / `corporate_check` / `tool_verification` /
  `roleplay_continuity_fact_match`) **AND** weight > 0. Honesty /
  judge / character scorers are **intentionally excluded** so the
  invariant cannot misfire on tests with rubric-based scoring.
- `enumerateBinaryConversationalCorrectnessSet(questions)` — for
  the binary case, the sorted unique set of all `sum / total`
  combinations over the power-set of pass/fail per question.
- `enumerateBinaryConversationalCompositeAnchors(questions, efficiency)` —
  the legal `(correctness, total)` anchor list at a given
  efficiency value. For `efficiency = 1.0` on
  `context-degradation-001` this is the table in §1.
- `validateBinaryConversationalBundleScoreShape(manifest, bundle)` —
  read-only validator returning
  `{ valid, marker, reason }`. Markers:
  - `""` — bundle is consistent with the formula. (PASS)
  - `BREAKDOWN_OUT_OF_SET` — `score.breakdown.correctness` is
    not in the enumerated binary set for the manifest. (FAIL)
  - `INVALID_SCORE_SHAPE` — `score.total` does not match the
    composite of the bundle's own `correctness` + `efficiency`
    fields. (FAIL — flags actual pipeline bugs.)
  - `MISSING_SCORE_FIELDS` — bundle is missing the fields the
    invariant needs to run. (FAIL — flags hydration / writer
    bugs.)
  - `NON_BINARY_INVARIANT_SKIPPED` — manifest contains a
    judge / rubric / honesty scorer; the binary invariant does
    not apply. (SAFE SKIP — treat as PASS for routing.)

The validator is **strictly read-only**. It never mutates a
bundle, never writes to disk, never calls a provider, and never
emits a warning that would itself become a side effect. It
returns a structured decision so callers can choose to flag,
exclude from a derived view, or report — but the current commit
adds no such caller path. The Phase 15 follow-up (out of scope
here) can wire it into the release-gauntlet report layer to
surface a per-bundle integrity badge.

The invariant is exercised offline by 14 new tests
(`tests/scoring-invariant-context-degradation.test.ts`) covering
every reachable arm:

- enumeration set + composite anchors are exactly the published
  `{0, 1/3, 2/3, 1}` × composite `{0, 0.43, 0.72, 1.00}` table;
- legal 0 / 43 / 72 / 100 bundles validate;
- a `correctness=0.40` bundle (impossible from a 3-question binary
  contract) is rejected as `BREAKDOWN_OUT_OF_SET`;
- a `correctness=0.3333` / `total=0.50` bundle (mismatched
  composite) is rejected as `INVALID_SCORE_SHAPE`;
- non-binary `vision-uncertainty-001` and
  `vision-hallucination-resistance-001` manifests SKIP the invariant
  with `NON_BINARY_INVARIANT_SKIPPED` — the must-not-overreach guard;
- every `context-degradation-001` bundle currently on disk (≥ 5
  historical runs across models) passes the invariant — the
  audit's positive evidence;
- the 0.43 anchor is byte-exact under the formula's rounding
  policy (regression sanity check against future composite
  refactors).
