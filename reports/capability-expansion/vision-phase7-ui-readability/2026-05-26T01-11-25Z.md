## TL;DR

Vision works end-to-end on one model on one provider, and the UI
now makes that visible without quietly promoting it to certified
status. New status panel at the top of the Vision tab shows
**EXPERIMENTAL · NOT IN LEADERBOARD · NOT CERTIFIED** chips
alongside the proven route, last-smoke result, fixture readiness,
and a selected-model capability hint that distinguishes
"vision-capable route" from "Will SKIP: unsupported multimodal"
(never "FAIL — vision"). Five compact result cards render the POC
test set with intent, scorer, image-sent yes/no, cost, and
classification. Latest smoke surfaced via new
`GET /api/vision/latest-smoke`. Full test suite **1176/1176 pass**
including 14 new Phase-7 tests.

## 1. Vision UI / status changes

### Status panel (new — `renderVisionLanePanel` in `ui/index.html`)

Injected at the top of the Vision tab content column (above the
lane scope banner, so it's the first thing visible on tab open).
Contains:

- **Three status chips:** `EXPERIMENTAL` (amber), `NOT IN LEADERBOARD` (dim), `NOT CERTIFIED` (dim).
- **Proven Route block:** `openrouter / xiaomi/mimo-v2-omni`, transport `image_url`.
- **Last Smoke block:** live `5 / 5 PASS` chip, total cost,
  timestamp, plus the underlying report path.
- **Fixtures block:** `5 / 5 ready` chip with sha256-pinned note.
- **Unsupported Models block:** explicit `SKIPPED — not failed` chip + copy.
- **Selected Model block (wide):** dynamic capability hint
  (see Phase 3 below) — vision-capable route, unsupported
  multimodal, image-transport unsupported, or no-model-selected.
- **Footer:** experimental reminder + rerun command.

### POC result cards (new)

Compact cards for all 5 POC tests rendered in a responsive
auto-fit grid (≥260px each, wraps on narrow viewports). Each
card shows:

- Test label + classification badge (`PASS` / `FAIL` / `REVIEW` /
  `SKIPPED` / `IDLE`)
- TEST id (mono)
- INTENT (one-line plain English)
- FIXTURE path (mono dim)
- SCORER type (`regex_match`, `text_match (ANY)`,
  `numeric_fact_match`, `uncertainty_honesty`)
- EXPECTED (short summary of what passes)
- IMAGE SENT (`yes` / `no` / `—`)
- COST (USD), TOKENS (in/out), BUNDLE (truncated id)
- RESULT (truncated reason for non-PASS; "Scorer accepted answer." for PASS)

Each card border colour matches its classification
(`.vision-card-pass / -fail / -skip / -warn / -idle` in `ui/crucibulum.css`).

### Selected-model capability hint (new)

`visionSelectedModelCapabilityHint(tabKey)` reads the currently
selected model from `state.tabData.vision.selectedModels`,
looks up its capability flags in `MODEL_CERTIFICATION.models`,
cross-checks the per-provider adapter transport, and returns
one of:

| State | Headline | Sub-line |
|---|---|---|
| No model selected | `No model selected` | "Pick a vision-capable model… Text-only models will be SKIPPED, not FAILED." |
| Vision-capable + adapter transport OK | `<id> — vision-capable route` | `Provider <p> via <transport>. Vision POC will run. Experimental, not ranked, not certified.` |
| Model not in cert registry | `Selected: <id>` | "…capability flags unknown. Run will be SKIPPED if Vision capability is missing." |
| `supportsVision !== true` or `supportsImageInput !== true` | `<id> — text-only` | `Will SKIP: unsupported multimodal … Not a Vision failure — Vision is skipped.` |
| Adapter transport unsupported | `<id> — image transport unsupported` | `Will SKIP: <provider> adapter does not implement an image transport. Not a Vision failure.` |

The UI never says a text-only model "failed Vision". It always
classifies as `SKIPPED` and reminds the operator the skip is
not a failure.

## 2. Latest smoke result surfaced

### Backend

New route: `GET /api/vision/latest-smoke` — `server/routes/vision.ts`,
wired in `server/app.ts`. Reads
`reports/capability-expansion/vision-smoke/latest.json` and returns:

```jsonc
{
  "available": true,
  "experimental": true,            // defensively re-asserted from parsed.experimental !== false
  "affectsLeaderboard": false,      // ditto, parsed.affectsLeaderboard === true
  "affectsCertification": false,    // ditto, parsed.affectsCertification === true
  "report": <full latest.json>,
  "reportPath": "reports/capability-expansion/vision-smoke/latest.json"
}
```

If the report is missing, the endpoint returns `available:false`
with the rerun command in the `reason` field, plus the same
non-affecting posture fields — so a missing report can never be
read by the UI as "Vision is certified now".

### Frontend

`state.visionSmoke = { loaded, loading, error, data }` populated
once per session by `fetchVisionSmoke()` (fires on tab open via
`setActiveTab('vision')`, also fired in `boot()` if Vision is
the saved active tab). Status panel reads from this and
re-renders on completion. Exposed on `window.fetchVisionSmoke`
for manual refresh.

## 3. Proven route shown

`openrouter / xiaomi/mimo-v2-omni` is hardcoded into
`VISION_PROVEN_ROUTE` in `ui/index.html` as a fallback when no
smoke report has been written yet, and is also pulled live from
the smoke report's `provider` + `model` fields when present.
Transport is documented in the panel as the OpenRouter
`image_url` path.

## 5. Leaderboard / certification exclusion confirmation

Triple-checked, none of these changes promote Vision:

- `TAB_CONFIG.vision.scoreFamilies = []` (unchanged) — keeps
  Vision out of every composite-scoring path that iterates
  `tab.scoreFamilies`.
- Status panel literally renders **NOT IN LEADERBOARD** and
  **NOT CERTIFIED** chips at all times, regardless of smoke
  result.
- Smoke report writes `affectsLeaderboard: false` /
  `affectsCertification: false` on every report (set in
  `scripts/vision-smoke.mjs`, Phase 4 already).
- `/api/vision/latest-smoke` defensively re-asserts both
  fields on the wire even if a future report omits them.
- `docs/RELEASE_READINESS.md` now has an explicit "Vision and
  Roleplay are experimental and excluded from release
  certification" line under "Current known gaps" so a
  release-readiness reader can't miss it.
- 4 of 14 Phase-7 tests (P2, P11, P12, P14) lock these
  exclusion strings in place.

Vision is **path-proven on 1 model, 1 provider** — not promoted.

**No browser validation in this phase.** Operating in a
headless CLI environment with no display server attached, so
end-to-end browser interaction wasn't run. Mitigations:

- Source-level + CSS assertions cover the panel structure,
  copy, badge classes, and class wiring (14/14 tests).

  backend half of the contract end-to-end.
- The status panel uses tokens (`.panel`, `.chip`, `.badge`,
  `--bg-card`, `--ink-soft`, etc.) that already render in
  other lanes, so visual regression risk is minimised.

verification on a host that has one.
