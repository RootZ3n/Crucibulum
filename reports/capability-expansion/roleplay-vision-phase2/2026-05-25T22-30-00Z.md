## 1 · Cleanup flake root cause and fix

**Test:** `cleanupStaleArtifacts › respects maxAgeMs option`

**Root cause:** the test scanned the production `./runs/` directory
(970+ files) twice and asserted `scanned1 === scanned7`. Between the
two `readdirSync()` calls, parallel tests (release-gauntlet,
model-certify, conversational-runner) could write or remove a bundle
— making `scanned` differ by exactly 1. The assertion was correct in
spirit (the option should not change the scan target) but the scan
target was shared, mutable global state.

**Fix:** deterministic, NOT quarantine.

- `core/cleanup.ts` — added `runsDir?: string` to `CleanupOptions`
  (with pass-through on `getCleanupStats`); replaced the module-load
  constant with `resolveRunsDir(override)` evaluated per call.
- `tests/cleanup.test.ts` — `mkdtempSync` per `describe` block, seeded
  with exactly 5 deterministic entries; both `maxAgeMs` calls scan
  the same temp directory; asserts `scanned === 5`.

**Verification:** 5 consecutive test runs → 4/4 pass each time (was:
occasional 3/4). Full audit at
`reports/stability/cleanup-flake/2026-05-25T22-15-00Z.md`.

## 2 · New skip classifiers

`core/skip-classifiers.ts` defines four codes with consistent labels,
reasons, and policy flags:

| Code | When | UI label |
|---|---|---|
| `SKIPPED_FIXTURE_MISSING` | Vision manifest's `image_fixture.sha256` starts with `TBD` (or the file is absent) | Skipped · fixture missing |
| `SKIPPED_UNSUPPORTED_MULTIMODAL` | Vision task selected for a model without `supportsVision` + `supportsImageInput` | Skipped · model has no image input |
| `SKIPPED_UNSUPPORTED_ROLEPLAY_PROFILE` | Roleplay task selected for a model that declares `supportsRoleplay: false` | Skipped · model opted out of roleplay |
| `SKIPPED_EXPERIMENTAL_FAMILY` | Family is `experimental: true` and the operator hasn't explicitly opted in | Skipped · experimental family |

Each carries `countsAsFail: false`, `countsAsPromotion: false`,
`affectsLeaderboard: false`, `affectsCertification: false`. Public
helpers: `isSkipClassification`, `isExcludedFromLeaderboard`,
`isExcludedFromPromotion`, `visionFixtureMissing`,
`modelCanRunVision`, `modelCanRunRoleplay`, `preflightSkipCheck`.

## 3 · Missing fixture behavior

`preflightSkipCheck(manifest, capabilities)` is called at the top of
`runConversationalTask` BEFORE `adapter.chat()` is ever invoked.
For vision tasks with `TBD-fixture-not-yet-committed`:

- Runner returns `buildSkipResult(...)` immediately.
- Bundle records: `family: vision`, `task.id`, fixture path, skip
  reason, `verdict.evidence.skip_classification`,
  `verdict.evidence.fixture_path`, `verdict.evidence.capability_required`.
- `score.skipped: true` + `score.skip_classification: <code>` — so
  the leaderboard aggregator can identify and exclude it.
- `usage.tokens_in/tokens_out/cost_usd = 0` — proves no provider spend.
- `verdict.completionState: "SKIPPED"`, `failureOrigin: null`,
  `countsTowardModelScore: false`, `countsTowardFailureRate: false`.
- No `FAIL_PRODUCT`, no `FAIL_PROVIDER`, no `FAIL_CONFIG`.

## 4 · Unsupported multimodal behavior

Same preflight gate. For vision tasks selected on a model that
doesn't declare `supportsVision` + `supportsImageInput`:

- `SKIPPED_UNSUPPORTED_MULTIMODAL` returned immediately.
- Same auditable bundle shape as above with the model's capability
  snapshot embedded in `verdict.evidence`.
- No adapter call, no spend, no failure attributed to the model.

The default in `MODEL_CERTIFICATION.capabilityDefaults` is
`supportsVision: false` — so the only models that DON'T get skipped
are the ones explicitly opted in (`mimo-v2-omni` today).

## 5 · Leaderboard / certification exclusion confirmation

- `isExcludedFromLeaderboard()` returns `true` for every `SKIPPED_*`
  code AND `NEEDS_REVIEW` AND `FAIL_PROVIDER` AND `FAIL_CONFIG`
  AND `BLOCKED_COST_CAP`. Pinned by tests PH11.
- `isExcludedFromPromotion()` mirrors the same set. Pinned by PH12.
- `scripts/model-certify.mjs` `classifyTier()` filters skip codes out
  of the scoring set BEFORE making a tier decision — so a campaign
  that produces 5 PASS + 1 SKIPPED is treated as 5 PASS for tier
  purposes. Pinned by PH8.
- An all-skip campaign (no scoring results) returns `EXPERIMENTAL`
  not a promoted tier — pinned by the `scoring.length === 0` branch
  in `classifyTier`.
