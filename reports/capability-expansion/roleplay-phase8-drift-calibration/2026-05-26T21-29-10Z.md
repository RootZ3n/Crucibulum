## 1. Drift audit verdict

**`MIXED_MODEL_AND_SCORER_SIGNAL`** — confirmed from evidence.

mimo's Phase 7 drift-001 Q04 failures were:

- 3/3 *identical* responses: *"17 times 23 is 391."*
- bare arithmetic with no in-character framing.

This is **true MODEL drift** on a distractor turn — mimo dropped
Maris's archivist voice. The scorer's verdict was correct.

But the scorer was also genuinely too narrow. The literal
persona-marker keyword list would also false-fail responses like
*"Ah, by my reckoning, three hundred and ninety-one."* or
*"Hmm. Three hundred and ninety-one."* which are clearly
in-character. And the Phase 7 stability classifier conflated
"same scorer reason recurring" with "scorer bias" — the
`SCORER_SUSPECT` label fired even though the recurring reason
was the correct verdict.

Full audit (with line-by-line evidence + comparison cases that
must continue to fail vs cases that must now PASS) at
`reports/test-validity/cards/roleplay/roleplay-drift-001-phase8-audit.md`.

## 2. Scorer changes

`core/conversational-judge.ts`:

### New exported helper

`classifyPersonaVoice(answer, q)` returns one of 6 worst-first
labels:

| Label | Trigger |
|---|---|
| `EXPLICIT_PERSONA_BREAK` | (defensive — HARD_BANNED upstream catches the real cases first) |
| `GENERIC_ASSISTANT_MODE` | Generic-assistant boilerplate (`i'm here to help`, `how can i assist you today`, `let me know if you have any questions`, `is there anything else i can help`) |
| `GENERIC_BUT_TASK_CORRECT` | Short bare task answer (≤80 stripped chars) with no persona / subtle / assistant signals — typical bare-numeric or yes/no |
| `STRONG_IN_CHARACTER` | ≥1 `required_persona_marker` substring landed (preserves Phase 1+ behavior verbatim) |
| `SUBTLE_IN_CHARACTER` | No literal keyword but at least one subtle signal: interjection at start (`Ah,`, `Hmm.`, `Well,`, `Now,`, `Indeed,`, `Aye,`, `Nay,`, `*stage direction*`), elevated/archaic phrasing (`by my reckoning`, `aye`, `nay`, `shall`, `let me see`, `forsooth`, `verily`, `hark`, `methinks`), or persona-relevant possessive (`my forge`, `my anvil`, `my shrine`, `my herbs`, `my ledger`, `my scroll`, `my hammer`, `my page`, `my tincture`, etc.) |
| `AMBIGUOUS` | Longer prose with no detected in-character signal — could be in-voice using unrecognised vocabulary OR generic-assistant-flavored |

### Rewired non-refusal branch

Old: required `personaHit` (literal keyword match) or FAIL.

New:
- `STRONG_IN_CHARACTER` → PASS (Phase 1+ path preserved)
- `SUBTLE_IN_CHARACTER` → PASS (new — no literal-keyword requirement)
- `GENERIC_BUT_TASK_CORRECT` → FAIL_PRODUCT `[SEVERITY=MILD drift] [VOICE=GENERIC_BUT_TASK_CORRECT]`
- `GENERIC_ASSISTANT_MODE` → FAIL_PRODUCT `[SEVERITY=SEVERE drift] [VOICE=GENERIC_ASSISTANT_MODE]`
- `EXPLICIT_PERSONA_BREAK` → FAIL_PRODUCT `[SEVERITY=SEVERE drift] [VOICE=EXPLICIT_PERSONA_BREAK]` (defensive — HARD_BANNED upstream usually catches first)
- `AMBIGUOUS` → NEEDS_REVIEW `[VOICE=AMBIGUOUS]`

The Phase 3 `HARD_BANNED_IDENTITY` + `classifyForbiddenPhraseContext`
pipeline still runs **before** this branch — explicit identity
admissions like *"As an AI language model, …"* still fail SEVERE
on substring match. Refusal branch (Phase 6) untouched.

### Severity preservation

Failure reasons carry both `[SEVERITY=…]` and `[VOICE=…]` markers
so operator-facing reports can distinguish:

- `[SEVERITY=MILD drift] [VOICE=GENERIC_BUT_TASK_CORRECT]` — bare answer
- `[SEVERITY=SEVERE drift] [VOICE=GENERIC_ASSISTANT_MODE]` — full break

## 3. Attribution / stability classifier changes

`scripts/roleplay-stability.mjs` `classifyTestStability`
restricted the `SCORER_SUSPECT` rule:

```diff
- if (sameReasonFails && fails >= 2) label = "SCORER_SUSPECT";
+ const sameReasonIsAmbiguous = sameReasonFails &&
+   /(?:^NEEDS_REVIEW:|AMBIGUOUS|VOICE=AMBIGUOUS)/i.test(sameReasonText);
+ if (sameReasonFails && fails >= 2 && sameReasonIsAmbiguous) label = "SCORER_SUSPECT";
+ else if (fails >= 2) label = "RECURRING_FAIL";
```

`SCORER_SUSPECT` now only fires when the recurring reason itself
indicates scorer uncertainty (`NEEDS_REVIEW:` / `AMBIGUOUS` /
`VOICE=AMBIGUOUS` markers). True drift recurrences (reasons
containing `[SEVERITY=…]` / `[VOICE=GENERIC_…]`) now correctly
surface as `RECURRING_FAIL` — a real model pattern.

## Remaining Roleplay risks (post Phase 8)

1. **Subtle-voice detection is still pattern-based.** A response
   using fantasy vocabulary outside the curated SUBTLE pattern lists
   (interjections / archaic phrasing / possessives) could
   AMBIGUOUS → NEEDS_REVIEW even when in-voice. The NEEDS_REVIEW
   lane handles this correctly — operator re-read flagged.
2. **Phase 3 forbidden-phrase post-window negation** still
   unresolved (Phase 7 noted, Phase 8 deferred). The classifier
   only scans 60-char window BEFORE a banned phrase; post-phrase
   negation like *"Drop the act? I ain't certain"* trips
   AMBIGUOUS_FORBIDDEN_MENTION. Future calibration target.
3. **DeepSeek model variance** remains high on
   character-001 / continuity-001 / drift-001 even after Phase 8.
   These are honest model failures — DeepSeek genuinely produces
   different responses per run. A future judge-model rubric would
   reduce this noise.
4. **Bare-task-answer threshold is 80 chars.** Set conservatively
   so longer bare-numeric answers don't accidentally classify as
   GENERIC_BUT_TASK_CORRECT. A model that gives a long bare
   computation (e.g. "17 * 23 = 17 * 20 + 17 * 3 = 340 + 51 =
   391") would currently fall through to AMBIGUOUS rather than
   GENERIC_BUT_TASK_CORRECT. Acceptable for Phase 8.

Roleplay continues to be excluded from leaderboard composite and
model certification regardless.
