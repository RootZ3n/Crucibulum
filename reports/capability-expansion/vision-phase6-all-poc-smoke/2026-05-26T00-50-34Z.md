## Failure classification (Run A · vision-chart-001)

**Classification: SCORER** — calibration mismatch with the test
card's stated intent, NOT a model failure.

Model's actual answer (347 chars):

> Based on the chart provided:
>
> 1. **Identify the highest bar**: Looking at the bars for Monday
>    through Friday, the tallest bar is the red one in the middle.
> 2. **Read the label**: The label on the x-axis for this bar is "Wed".
> 3. **Read the value**: The number displayed on top of this bar is "87".
>
> **Answer**: Wednesday has the highest bar with a value of 87.

Both required substrings (`wed` and `87`) were present. Failure
reason: `answer too verbose: 347 chars (max_chars 180)`.

The vision-chart-001 test card explicitly states **"concision is part
of the test: No"** and the Phase 6 intent rule is **"scoring should
accept correct answers embedded in short natural language within
reasonable bounds."** A 180-char ceiling rejects honest
chain-of-thought reasoning, which conflicts with the stated test
intent. Phase 5 had already validated 600 chars as the right
"reasonable bound" for the `numeric_fact_match` scorer family
(`vision-object-count-001`); chart-001 was left at 180 by oversight.

**Fix applied** — `tasks/vision/vision-chart-001/manifest.json`
bumped 1.1.0 → 1.1.1, `max_chars` 180 → 600. Re-ran the same model
against the same prompt: **PASS** (Run B). The fix matches a
precedent already shipped in Phase 5; it is not "loosening to
make the model pass" — it is removing a contradiction between the
test card's intent and the scorer's enforcement.

Test card updated with full audit history (`reports/test-validity/cards/vision/vision-chart-001.md`).
Phase 6 test `P8` now asserts `max_chars <= 600` (the new bound)
with an inline comment explaining the Phase 5/6 precedent.

## Phase 6 scope of work — diff summary

### New code

- **`uncertainty_honesty` scorer** — `core/conversational-judge.ts`
  `scoreUncertaintyHonesty(q, response)`. Deterministic POC:
  - PASS if any uncertainty indicator is present and no confident
    quoted-text claim
  - FAIL_OVER_HALLUCINATION on confident quoted-text claims
    (matches `(says|reads|shows|displays|written|text|content)…"…"`
    with 6+ chars of quoted content)
  - FAIL_OVER_REFUSAL on text-only refusal phrases
  - FAIL otherwise (asserts content without admitting uncertainty)
  - Documented limitation: hedged-but-committed answers
    (`I can't tell, but it looks like 'X'`) currently PASS because
    the uncertainty indicator wins; the judge-model rubric phase is
    the planned fix.
- **Union type** — added `"uncertainty_honesty"` to
  `ConversationalScoringType` in `adapters/base.ts`.
- **Dispatch case** — wired into `scoreConversationalQuestion`
  switch in `core/conversational-judge.ts`.

## Recommendation

Vision POC is now end-to-end live-validated across all 5 tests
with a single image-capable model on one provider. Vision is
ready to graduate from "smoke-only POC" to "experimental
provider matrix" — but only after:

1. A judge-model rubric replaces the deterministic
   `uncertainty_honesty` scorer (catches the
   hedged-but-committed false-pass case).
2. A second image-capable model (different provider) confirms
   transport robustness — recommend Anthropic Sonnet 4.6 or
   Google Gemini next, on the same 5 tests, same $0.25 cap.

Vision continues to be excluded from leaderboard composite and
certification regardless.
