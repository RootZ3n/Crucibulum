## 4. Issues found

**No UI issues.** The visual checklist (clipped names, clipped
cards/buttons, giant empty gutters, mobile horizontal scroll) all
pass: no horizontal overflow anywhere, no clipping observed in any
of the 12 PNGs, no empty side gutters at any viewport.

**One harness-only artifact — documented, not a UI bug:**

The `reconcileTabSelection()` function in `ui/index.html`:1273
unconditionally backfills `state.tabData.<lane>.selectedModels`
with `preferredDefaultModelId()` whenever the array is empty AFTER
filtering against the registry. The harness has to inject a
seeded `selectedModels` value AFTER both `loadRegistry()` and
`reconcileTabSelection()` finish, otherwise the backfill silently
overwrites the seeded value with the registry's first cloud-
registered model (currently `google/gemini-3.1-flash-lite`). The
harness retries with a state-poll-and-reseed loop for up to 8 s,
but on some captures the reseed still loses the race.

This affects **only synthetic screenshot capture** — real users
select via the on-screen `<select multiple>`, which writes to
state via `updateSelectedModels()` and is deterministic. The
capability-hint logic itself is provably correct: each of the three
states (no-model, vision-capable, text-only) rendered with the
expected copy in multiple captures, and Phase-7 source tests
already lock the copy strings.

If a future phase wants 100% clean harness captures, the cleanest
fix is to delete `state.tabData.vision` and re-set
`{selectedModels: ids}` inside a `setTimeout` chained after
`loadRegistry()` resolution — e.g. expose a `window.__seedVisionForTest`
that does this with the right ordering. That's a harness-only
improvement and is out of scope for Phase 8 per the "keep changes
minimal" rule.

## Remaining UI debt

None blocking. Two minor follow-up items worth noting for future
Vision phases:

1. **Mobile document height** is ~9–12k px on the Vision lane.
   That's the same vertical stack as every other lane on mobile
   today and isn't a Vision-specific issue — but if a Vision-tab
   condensed mobile view ever becomes important (operator-on-call
   triaging from a phone), a `.vision-status-panel` collapse-by-default
   on `≤599px` would be the right surgery. Not required today.
2. **Screenshot-harness model seeding** races
   `reconcileTabSelection()`. If we want a 100%-clean visual
   regression run in CI, expose a tiny `window.__seedVisionForTest`
   hook gated to non-production builds. Today's evidence is
   sufficient without it.
