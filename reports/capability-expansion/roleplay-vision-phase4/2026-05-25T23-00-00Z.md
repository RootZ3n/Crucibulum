## 1 · Skip-card rendering summary

New `renderSkipCards(result)` in the focused-run inspector. Mounted
ABOVE the sub-question failure cards so a skipped run is the first
thing the operator sees when inspecting a Skipped bundle.

The card explicitly says **"Skipped, not failed"** and uses a
dashed grey border (`.skip-card` CSS) so it cannot be confused with
red fail cards. It surfaces:

- `SKIPPED` badge + skip-code pill (e.g. `SKIPPED_FIXTURE_MISSING`)
- Family · skip reason · provider · model
- `Provider called: NO` (skip badge)
- `Tokens spent: 0 in · 0 out`
- `Cost: $0.0000`
- `Affects leaderboard: NO` (skip badge)
- `Affects certification: NO` (skip badge)
- Fixture path (when present)
- Expected vs Actual sha256 (when present — for hash-mismatch skips)
- Required capability (when present — for unsupported-multimodal)

## 2 · Image transport path implemented

**OpenRouter only** (Phase 4 deliberately stops here per spec).

Changes:
- `ChatMessage.content` widened from `string` to `string | ChatContentPart[]`
- New types `ChatContentTextPart` + `ChatContentImagePart`
- OpenRouter `callAPI` + `buildOpenRouterChatBody` accept content as
  `unknown` → forward verbatim (OpenAI/OpenRouter schema is identical
  for both string and multimodal content arrays)
- Other adapters (anthropic, openai, ollama, minimax, zai, google,
  peh, harness-mock) widened their content typing the same way
  but defensively coerce non-string content via `JSON.stringify`
  since they're text-only today. Vision routes never reach them
  because `preflightSkipCheck` gates on
  `capabilities.imageTransportImplemented`, which only the
  vision-smoke script flips to `true` for the OpenRouter route.
- Conversational runner: for vision-family tasks past preflight,
  reads fixture bytes (already-hash-validated by preflight),
  base64-encodes, attaches as `image_url` content part on the
  question turn.
- `ConversationalFamily` union extended with `"roleplay"` and
  `"vision"`; manifest loader searches those directories.
