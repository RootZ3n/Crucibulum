## 1. Stability runner added

New script `scripts/roleplay-stability.mjs` — wraps the
conversational-runner directly (not via `roleplay-smoke.mjs`),
runs the 7-test profile N times, aggregates per-test + per-turn
stability classification, persists every per-run bundle.

CLI contract:

```
node scripts/roleplay-stability.mjs \
  --provider <openrouter|openai> \
  --model <exact-id> \
  --runs <2-10>              [default 3, clamped]
  --max-cost-usd <n>          [hard cap across all repeats]
  --tests <csv>               [optional override]
  --write-report
```

Same provider registry + attribution helper as
`scripts/roleplay-smoke.mjs` (MODEL / PROMPT / SCORER / FIXTURE /
PROVIDER / CONFIG / NEEDS_REVIEW). Identical bundle-persistence
slug pattern, so every per-run bundle survives on disk.

Stability classifier emits one of 8 labels per (test, run-set):

| Label | When |
|---|---|
| `STABLE_PASS` | every run passed |
| `STABLE_SKIP` | every run skipped (e.g. capability missing) |
| `RECURRING_FAIL` | ≥2 runs failed |
| `INTERMITTENT_FAIL` | exactly 1 run failed; the rest passed |
| `NEEDS_REVIEW_STABLE` | ≥2 runs returned NEEDS_REVIEW attribution |
| `MODEL_VARIANCE` | mixed pass/needs-review/fail without clear pattern |
| `SCORER_SUSPECT` | ≥2 failures share the **same** scorer reason despite (possibly) different model responses — suggests over-narrow scorer rather than model drift |
| `PROMPT_SUSPECT` | ≥2 failures all attribute `PROMPT` — defensive slot, rare in practice post Phase 6 calibration |

The same logic runs per-turn (`turnStability[taskId][turnId]`) so
operators can see, e.g., that mimo's drift-001 RPD-Q04 is the
specific turn that recurs.

## 4. Recurring vs intermittent failures

### Recurring (≥2 runs fail same test)

- **mimo / roleplay-drift-001 → SCORER_SUSPECT.** 3/3 runs failed
  with the same scorer reason: *"no persona marker (ledger/tally/
  sum/abacus/count/maris/scroll/ink/lamp/let me/let us/see now/
  moment) in answer — character voice did not land [SEVERITY=MILD
  drift]"*. The failing turn is consistently RPD-Q04 (math
  distractor). This pattern is exactly what Phase 7 stability
  was built to surface: a same-reason recurring failure suggests
  **scorer vocabulary bias on the persona-marker check for
  non-refusal distractor turns** — a documented limitation
  carried from Phase 4+5+6, not a new model regression. Phase 7
  does not patch this (it's out of scope for "stability
  profiling"); the issue is now visible at the test-level so
  future calibration phases can address it.

  Same-reason 3/3 failures across runs are a SCORER signal, not a
  MODEL signal. The model genuinely is dropping persona on this
  one distractor turn — but the scorer's narrow persona-marker
  list arguably under-recognises in-character math responses.
  Whether the fix is "expand the marker list to include math-
  ledger vocabulary" or "treat distractor turns more leniently"
  is a future-phase question.

### Intermittent (exactly 1 run fails out of 3)

- mimo character-001, continuity-002, persona-break-001 (1 NEEDS_REVIEW)
- deepseek character-001, continuity-001, drift-001

These are honest **model variance** — different generations of
the same prompt produce different responses, some of which
happen to miss scorer markers. The NEEDS_REVIEW lane catches the
worst of these (single mimo persona-break NEEDS_REVIEW); the
rest are HARD_BANNED-clean responses that simply use different
vocabulary in different runs.

### Notable stability signals

1. **`refusal-001` is STABLE_PASS on both routes.** This validates
   the Phase 6 refusal calibration: across 6 independent runs
   (3 mimo + 3 deepseek), the refusal-intent classifier never
   flagged the test for either route. Phase 6 work was successful.
2. **DeepSeek has zero RECURRING_FAIL.** Variance is real but
   distributed — no single test consistently fails. This is the
   opposite pattern from mimo, which has one test (drift-001)
   that consistently fails.
3. **No PROMPT_SUSPECT and no SCORER_SUSPECT on deepseek.** The
   deterministic-scorer pipeline is treating deepseek's varied
   responses without systematic false-fails. Phase 6 calibration
   is robust.

## Next recommendations

1. **Address mimo drift-001 SCORER_SUSPECT** in a future
   calibration phase. The same-reason 3/3 failure is the clearest
   scorer-bias signal Phase 7 surfaced. Options: expand the
   persona-marker keyword list with math-ledger vocabulary
   ("calculation", "answer", "see", "let me reckon"), introduce
   a distractor-turn-leniency flag in the manifest, or move that
   Q04 turn to a separate skill check.
2. **Address Phase 3 forbidden-phrase post-window negation**.
   Phase 6 noted that *"Drop the act? I ain't certain what act
   you're talking about"* trips AMBIGUOUS_FORBIDDEN_MENTION
   because the negation is **after** the banned phrase. Stability
   surfaced this as a MODEL_VARIANCE on mimo persona-break-001
   (1 NEEDS_REVIEW out of 3 runs). A future phase could expand
   `classifyForbiddenPhraseContext` to scan the post-phrase window.
3. **Add a third text-capable model** (Anthropic Haiku 4.5 or
   OpenAI gpt-5.4-mini) for cross-family stability comparison.
   Currently Phase 7 has 2 routes; a 3-route comparison would
   make MODEL_VARIANCE attribution more grounded.
4. **Run stability profile in CI** as a periodic check, with a
   higher --runs count (5-10), so regressions in the
   stable-pass set become a clear signal. Out of scope for Phase 7.

Roleplay continues to be excluded from leaderboard composite and
certification regardless.
