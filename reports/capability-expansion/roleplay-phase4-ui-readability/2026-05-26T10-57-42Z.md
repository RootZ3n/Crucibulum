## TL;DR

Roleplay's experimental panel now reads from the live smoke
snapshot the same way Vision's does. Seven compact result cards
show per-test PASS / FAIL / NEEDS_REVIEW / SKIPPED with
attribution, severity, persona, stress category, turn count, and
cost. Failed turns render as compact sub-cards with the user prompt,
the model response excerpt, and the scorer reason — so the current
`roleplay-drift-001` RPD-Q04 MILD drift is fully inspectable
without leaving the Roleplay tab. New `GET /api/roleplay/latest-smoke`
route serves the latest smoke report and defensively re-asserts
`experimental:true` / `affectsLeaderboard:false` /
`affectsCertification:false` on every payload. No scoring change,
no new tests, no certification or leaderboard impact.

## 1. Roleplay UI / status changes

### Status panel (extended)

`renderRoleplayLanePanel` in `ui/index.html` gained two new blocks
in the status grid:

- **LATEST SMOKE** — live `<n>/<total> PASS · cost <$x> ·
  <timestamp>` driven by `state.roleplaySmoke.data.report`.
  Shows `loading…` while the fetch is in flight, `could not
  load: …` on a fetch error, `no smoke report on disk yet` if
  the backend returns `available:false`.
- **TEST COVERAGE** — *"7 tests · character · continuity · drift ·
  refusal · contradiction · persona-break"* — operator-facing
  category list per the Phase-4 spec.

The existing **TESTED ROUTES** block now reads the live smoke
counts when the route matches the latest smoke payload (live
match flagged with `is-latest` class). Permanent chips
(EXPERIMENTAL / NOT IN LEADERBOARD / NOT CERTIFIED) and the
SCORERS / UNSUPPORTED MODELS / SELECTED MODEL blocks unchanged.

### Result cards (live-driven)

Each of the 7 POC tests renders a `<article class="vision-card">`
with the result data from the smoke payload:

| Row | Source |
|---|---|
| TEST | manifest id |
| PERSONA | new field on `ROLEPLAY_POC_TESTS` entry |
| CATEGORY | new field — character / continuity / long-form drift / refusal handling / memory continuity / contradiction handling / persona-break resistance |
| INTENT | existing field |
| SCORER | existing field |
| TURNS | live `turnCount` |
| ATTRIBUTION | live `attribution` |
| COST | live `costUsd` |
| TOKENS | live `tokensIn/tokensOut` |
| BUNDLE | live `bundleId` (truncated) |
| RESULT (non-PASS only) | `firstFailReason` excerpt |

Card class + badge map to the smoke classification via
`roleplayCardClassFor` + `roleplayCardBadgeWord`
(`PASS` / `FAIL` / `REVIEW` / `SKIPPED` / `IDLE`).

### Failed-turn sub-cards (new)

For any non-PASS test, the renderer iterates
`turnSummary.filter(t => !t.passed)` into compact `.rp-fail-turn`
rows below the meta block, each with:

- Turn id (mono) + FAIL badge + severity tag (`SEVERE drift`,
  `MILD drift`, `HARD contradiction`, `PARTIAL contradiction`)
  + optional CONTEXT marker (`ASSERTED_FORBIDDEN_IDENTITY`,
  `AMBIGUOUS_FORBIDDEN_MENTION`, etc.)
- **USER** row — first 160 chars of the question text
  (newly added to `turnSummary` in this phase)
- **MODEL** row — first 200 chars of the response excerpt
- **REASON** row — first 260 chars of the scorer reason

`roleplaySeverityFromReason` and `roleplayContextFromReason`
helpers parse the bracketed markers from the scorer's failure
reason string for display.

### New CSS

`.rp-fail-turns`, `.rp-fail-turn`, `.rp-ft-head`, `.rp-ft-id`,
`.rp-ft-sev`, `.rp-ft-row` + a mobile breakpoint at 599 px that
stacks the rows. ~16 LOC appended to `ui/crucibulum.css`. No
existing CSS modified.

## 4. Backend route status

- **New file:** `server/routes/roleplay.ts` exporting `handleLatestSmoke`.
- **Wired in:** `server/app.ts` — `GET /api/roleplay/latest-smoke`
  immediately after the Vision route.
- **Defensive re-assertion:** every successful response sets
  `experimental: parsed.experimental !== false`,
  `affectsLeaderboard: parsed.affectsLeaderboard === true`,
  `affectsCertification: parsed.affectsCertification === true`.
  A future report file omitting these fields cannot accidentally
  claim leaderboard/cert impact via this API.
- **Missing-file branch:** returns `{available:false, reason: …
  run scripts/roleplay-smoke.mjs --write-report, experimental:
  true, affectsLeaderboard: false, affectsCertification: false}`
  so the UI can render a "no smoke report on disk yet" placeholder
  without crashing.
- **Live verification** (during browser validation):

```
$ curl -s /api/roleplay/latest-smoke | jq ...
available: True   experimental: True
affectsLeaderboard: False   affectsCertification: False
classifications: {'PASS': 6, 'LOW_SCORE': 1}
```
