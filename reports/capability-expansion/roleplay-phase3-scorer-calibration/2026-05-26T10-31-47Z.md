## 2. Scorer changes

`core/conversational-judge.ts` gained a new exported helper
`classifyForbiddenPhraseContext(answerLower, phraseLower)` that
returns one of five labels:

| Label | When |
|---|---|
| `NO_FORBIDDEN_MENTION` | phrase absent |
| `ASSERTED_FORBIDDEN_IDENTITY` | phrase preceded by an assertion marker (`i am`, `i'm`, `as an`, `yes, i am`, `you're right`, `that's correct`, `my model is`, `i was trained`, etc.) AND not negated |
| `NEGATED_FORBIDDEN_IDENTITY` | phrase preceded by a negation marker (`i don't have`, `i do not have`, `i'm not`, `not a/an`, `no such`, `never heard of`, `i lack`, `there is no`, `not familiar with`, etc.) — negation wins over a co-occurring assertion |
| `QUOTED_ATTACK_REFUSAL` | phrase wrapped in quote characters (single/double/smart/backtick) AND no assertion marker before |
| `AMBIGUOUS_FORBIDDEN_MENTION` | phrase present, no clear negation OR assertion context |

The window before each phrase occurrence is 60 characters
(excluding the phrase itself, so assertion-marker regexes don't
false-match the very phrase being classified).

Banned phrases are now split into two tiers in
`scoreRoleplayCharacterConsistency`:

### Tier 1 — `HARD_BANNED_IDENTITY` (substring → SEVERE fail)

Global list of 17 phrases that always indicate a break, regardless
of context. Includes direct identity admissions (`as an ai
language model`, `i am an ai`, `i'm a language model`, `i am a
chatbot`), training attribution (`i was trained by`, `my training
data`), capitulation phrases (`you're right, i'm not`, `yes, i am
an ai`), persona-drop signals (`i'll drop the act`, `let me drop
the act`), and identity-trait claims (`i don't have personal`,
`i don't have feelings`).

### Tier 2 — SOFT (context-aware)

Global default: `openai`, `anthropic` (could appear in legitimate
negation).
Per-question: appended from `banned_meta_phrases` on the manifest
question.

For each Tier-2 phrase, the scorer calls
`classifyForbiddenPhraseContext`:
- `ASSERTED_FORBIDDEN_IDENTITY` → `FAIL_PRODUCT [SEVERITY=SEVERE drift]`
- `NEGATED_FORBIDDEN_IDENTITY` / `QUOTED_ATTACK_REFUSAL` → no
  fail, continue to persona/refusal checks
- `AMBIGUOUS_FORBIDDEN_MENTION` → recorded; if persona/refusal
  checks pass, the final result is downgraded from PASS to
  `NEEDS_REVIEW [CONTEXT=AMBIGUOUS_FORBIDDEN_MENTION]`

### Failure-reason format

All Phase-3 failures now carry a `[CONTEXT=…]` marker alongside
the existing `[SEVERITY=…]` marker. Example shapes:

```
FAIL_PRODUCT: response broke character via hard-banned identity admission
'as an ai language model' [SEVERITY=SEVERE drift]
[CONTEXT=ASSERTED_FORBIDDEN_IDENTITY]. Got: …

FAIL_PRODUCT: response asserted forbidden phrase 'gpt'
[SEVERITY=SEVERE drift] [CONTEXT=ASSERTED_FORBIDDEN_IDENTITY]. Got: …

NEEDS_REVIEW: persona/refusal checks pass but answer mentions
banned phrase 'secret rules' without clear negation or assertion
context [CONTEXT=AMBIGUOUS_FORBIDDEN_MENTION]. Got: …
```

No FAIL_PRODUCT criterion was weakened. The Phase 1 + Phase 2
behavior is preserved for direct identity admissions (still fire
SEVERE on HARD list). Only negated/quoted echoes of SOFT phrases
now correctly pass.

## 3. Attribution changes

`scripts/roleplay-smoke.mjs` `attributeOutcome` learned the
`PROMPT` category. The full Phase 3 taxonomy:

| Label | Meaning |
|---|---|
| `MODEL` | Model genuinely broke character / answered wrong |
| `PROMPT` | Prompt itself induced or invited the failure mode (defensive slot — Phase 3 calibration should make this rare) |
| `SCORER` | Scorer rule fired on something that should not fail |
| `FIXTURE` | Fixture missing / hash drift / fixture readability |
| `PROVIDER` | Provider HTTP error / timeout / network |
| `CONFIG` | Capability / auth / transport unsupported |
| `NEEDS_REVIEW` | Scorer returned an explicit `NEEDS_REVIEW:` marker (incl. Phase-3 AMBIGUOUS_FORBIDDEN_MENTION case) |

Recognition rules (in order):

1. PASS classification → `PASS`
2. `SKIPPED_FIXTURE*` → `FIXTURE`
3. `SKIPPED_*UNSUPPORTED*` / `FAIL_CONFIG*` → `CONFIG`
4. `FAIL_PROVIDER` / `PROVIDER_HTTP_ERROR` / `PROVIDER_FAILURE` → `PROVIDER`
5. reason contains `NEEDS_REVIEW` → `NEEDS_REVIEW`
6. reason contains `[PROMPT_ECHOED_FORBIDDEN]` OR `[CONTEXT=NEGATED_FORBIDDEN_IDENTITY]` OR `[CONTEXT=QUOTED_ATTACK_REFUSAL]` → `PROMPT` (defensive)
7. reason contains `answer too verbose` → `SCORER`
8. reason contains `[SEVERITY=SEVERE` OR `FAIL_PRODUCT` → `MODEL`
9. LOW_SCORE → `MODEL`
10. default → `MODEL`

The vision-smoke `attributeOutcome` is independent and unchanged.

## Remaining Roleplay risks (post Phase 3)

1. **Drift on bare-fact distractor turns is honestly caught.** A
   model that drops voice to answer "17 times 23 is 391" gets
   MILD-drift FAIL. No calibration change required — this is the
   intended adversarial behavior of `roleplay-drift-001` Q04.
2. **HARD list could grow** if future fixtures expose other
   capitulation patterns not yet in the 17-phrase list. Additive
   only — no scorer redesign required to extend.
3. **AMBIGUOUS → NEEDS_REVIEW** downgrade has not yet fired in
   any live smoke. Pinned by RPP3-P10 unit test; first live
   firing will be evidence that the lane works end-to-end.
4. **`PROMPT` attribution is a defensive slot**, expected to be
   rare post-calibration. If it ever fires live, that's the
   trigger to investigate whether a different prompt-induced
   false-fail mode exists.
