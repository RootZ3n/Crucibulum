## 3. OpenAI image transport status

**Supported, end-to-end proven this phase.**

- `MODEL_CERTIFICATION.adapterImageTransport.openai` already declared
  `{supports:true, transport:'openai_image_url', maxImageMb:20, acceptedMimes:[png,jpeg,webp,gif], multiImage:true}` (pre-Phase 9).
- `adapters/openai.ts` forwards `messages` with `content: unknown`
  unchanged to OpenAI's `/v1/chat/completions`. OpenAI's API natively
  accepts the same content-part shape used by OpenRouter (and by
  Crucible's `core/conversational-runner.ts:618–628`). So the image
  injection code that already serves OpenRouter works for OpenAI with
  zero changes to the runner.
- One adapter bug surfaced and was fixed (Phase 9 commit body): the
  GPT-5 family rejects the legacy `max_tokens` parameter with HTTP 400
  *"Unsupported parameter: 'max_tokens' is not supported with this
  model. Use 'max_completion_tokens' instead."* Introduced
  `requiresMaxCompletionTokens()` to route GPT-5 + o-family models
  through `max_completion_tokens` (and to drop `temperature`, which
  GPT-5 chat completions also rejects). Test P5 locks the contract.

Fixture pipeline order (test P4):
1. `preflightSkipCheck` validates fixture path + sha256 against disk.
2. Only on success do we read the bytes, base64-encode, and attach as
   an `image_url` content part.
3. Provider payload includes both `text` and `image_url` parts.
4. Bundle records fixture path + mime + image_sent + provider/adapter
   + cost.

## Scorer calibration fix (caught during Phase 9 smoke)

Pre-Phase-9 `numeric_fact_match` rejected `"value of 87."` because
the `(?![\\d.])` lookahead rejected any period after the digit,
including sentence-ending periods. Fixed in `core/conversational-judge.ts`:

```
- const re = new RegExp(`(?<![\\d.])${v}(?![\\d.])`);
+ const re = new RegExp(`(?<!\\d)${v}(?!\\d)(?!\\.\\d)`);
```

The new regex still rejects digit-adjacency (no match in `"187"` /
`"870"`) and decimal continuation (no match in `"12.87"` /
`"87.5"`), but now allows trailing sentence punctuation. Phase-6
mimo test was unaffected because mimo's chart answer happened to
say `"87"` without a trailing period; gpt-5.4-mini's natural
chain-of-thought ends each fact with `"."`. Test P6 locks the new
regex shape in place.

Full suite is 1190/1190 pass after the scorer change, so no
existing test (including the older Phase-6 chart tests) regressed.
