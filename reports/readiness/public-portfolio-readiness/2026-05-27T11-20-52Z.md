## 6. Warnings (non-blocking)

- **No built-in auth.** Crucible has no authentication. The
  `POST /api/capabilities/vision/promote` endpoint can be hit by
  anything that can reach the bound port. Operators exposing
  Crucible beyond `127.0.0.1` must read `SECURITY.md` and put a
  network-layer gate (Tailscale, VPN, firewall, reverse-proxy
  auth) in front. This is documented in the README and in
  `SECURITY.md`; flagging here because it is the single most
  important caveat for a portfolio reviewer trying it themselves.
- **Local operator absolute paths in `docs/RELEASE_READINESS.md`.**
  The doc references `/mnt/ai/aedis/.env` and `/mnt/ai/crucible/.env`
  in an operator-narrative section. Not portable; not a security
  leak (no key content), but if a beta tester reads it they may
  ask "what is `/mnt/ai/aedis`?". Future-phase candidate: replace
  with `<crucible-env>` / `<aedis-env>` placeholders if it becomes
  friction. Not fixed this phase to stay within the "low-risk
  documentation/UI copy fixes" scope.
- **Receipt has absolute `receiptPath`.** This is intentional per
  Phase 16 doctrine and already framed in
  `docs/VISION_CAPABILITY_CERTIFICATION_SUMMARY.md` §8 ("local
  operator-owned"). Beta testers cloning the repo will see a path
  that does not exist on their machine; that is fine — the
  receipt is audit evidence of what the operator's machine
  recorded, not an artifact to be re-executed.

## 12. Final recommendation

**READY_FOR_PORTFOLIO_DEMO.**

Caveats:
- For **private beta**, operators must follow `SECURITY.md` to add
  network-layer access control (no built-in auth).
- For **public hosting** (beyond `127.0.0.1` or a private
  network), the auth caveat is hard-blocking. Crucible is not
  hardened against unauthenticated `POST` access to its API
  surface, including the `/api/capabilities/vision/promote`
  endpoint. The endpoint will refuse without the confirmation
  phrase, but the broader API still needs network-layer
  protection.

For a portfolio reviewer cloning and running locally with `npm
run serve`, every claim in the UI + README + docs is now backed by
an immutable receipt, a deterministic test, or a clear "operator-
local" caveat.
