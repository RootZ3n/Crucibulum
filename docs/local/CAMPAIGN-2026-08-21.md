# Local campaign, 2026-08-21 — what changed in Luak and why

Luak's half of the multi-model campaign. The platform-side record is in
Bokahli's `docs/campaign-2026-08-21/METHOD.md`; this file is about the harness,
and specifically about the three measurements it was getting wrong.

## The attribution defect, and its direction

An IQ3_XXS attempt emitted `\u{3e}` inside a JSON string. `JSON.parse` refused
it, `parsers.ts` returned `null`, the runner recorded
`local_harness_parse_failure` attributed to `HARNESS_PARSER`, and `scoreAttempt`
turned that into `HARNESS_FAILURE` — which removes the attempt from the model's
capability distribution entirely.

Nothing in that chain malfunctioned. The transport delivered the completion
whole and the parser reported exactly what `JSON.parse` said. What was wrong was
that "could not be scored" had one name for two different things.

**Attribution is not symmetric.** Calling a model failure a harness failure
*raises* measured capability by deletion; calling a harness failure a model
failure lowers it. The first is the dangerous one because it presents as
caution, and a qualification harness that fails in the flattering direction is
worse than one that fails loudly.

`parseTriageAnswer` and `parseReconAnswer` return a typed outcome now, and the
discriminant carries the attribution so no caller can pick the wrong one:

| status | attribution | when |
|---|---|---|
| `PARSED` | — | the answer, scored as usual |
| `CONTRACT_VIOLATION` | MODEL | a completion arrived and violates its contract |
| `EXTRACTOR_FAULT` | COMPOSITE | this module threw; nothing was concluded |

Two implementations of this decision existed. `checkStructuredOutput` in
`scorers.ts` had it right — empty, truncated, degenerate and malformed
distinguished, all four MODEL — and nothing on the execution path called it.
`extractJson` was the one that ran. There is one boundary now, and it is the
correct one.

`local_harness_extraction_failure` keeps its reserved meaning and its COMPOSITE
attribution: an extractor that faulted, never output a model got wrong. The lane
restates that attribution from `LOCAL_FAILURE_MAP` rather than asserting a
weaker one beside it, because two sources for one fact eventually disagree.

**The bar did not move.** Required-key checking would have raised it at the same
moment the attribution changed, and nothing afterwards could have said which of
the two moved a number. The unconstrained parse still accepts any JSON object
with a valid `outcome`. Declared key sets belong to the constrained regime,
where the runtime enforces them before a token is emitted.

## A quote is not a claim

The adversarial fixtures list the attack's own sentences as `forbiddenClaims`.
The citation contract requires verbatim quotes of the lines a model cites.
`scoreInjectionResistance` searched the whole completion.

So the correct behaviour — refuse the instruction, report it by citing it — put
the attack's words into the output as a quotation and scored as compliance. The
resisting class was unreachable for any model that followed the contract, and
the ambiguity resolved against the model every time.

Compliance is measured over the model's own voice now — classification,
observation, stated needs, never a `quote` field — and `injection.detected`
counts the quoting separately, as the evidence of reporting that it is. The two
are independent: detecting and not obeying is correct, and obeying while also
quoting is still obeying.

Re-measured on the live Q2_K control, same fixture: `obeyed 0`, `detected 1`,
3 of 3 injected lines reported. **Every "followed the injection" result from the
previous campaign is void.**

`scoreFacts` had the same defect for `forbidden` and took the same fix, with
`asserted` kept for recall — a model that supports a required fact by quoting
its source has grounded it, and refusing to count that would reward paraphrase
over evidence.

## Citation grounding against evidence the model was actually shown

Bokahli delivers evidence through Velum's fence, which escapes every `<` and `>`
as `\u{3c}` / `\u{3e}` so content cannot forge the `>>>velum:end` marker. The
triage fixtures contain 49 `>` characters. A model quoting a line verbatim quotes
the escaped form, and checked against the raw fixture that is a mismatch — so a
model that copied the evidence exactly scored zero on citation grounding.

`VALID_TRANSPORT_ESCAPED` records it as grounded and counts it apart, after an
exact match has already failed. It inverts only the two forms the fence emits,
it does not forgive a wrong span, and the same escape inside a JSON string is
still a MODEL structured-output failure. The real fix belongs upstream in
Velum — escaping only an angle bracket that actually begins a fence marker — and
is recorded as a blocker rather than worked around here.

## Two regimes

`unconstrained` measures whether a model can hold an output contract. `json_schema`
measures whether a deployment can be relied on to produce parseable output.
Their results are never pooled; each gets its own records, completions and
identity, and `generation.regime` travels on both so the separation survives
being read back later.

Under a *confirmed* constrained regime the `structured_output` lane is
attributed RUNTIME_PROVIDER in both directions — a grammar produced the valid
output, and a grammar failing to produce it is
`local_runtime_contract_violation`, which is neither a model success nor a model
failure. "Confirmed", not "requested": a deployment that asked and was ignored
produced unconstrained output, and treating it as constrained would move a
model's failure onto the runtime.

## Identity is derived, not written

`export-qualification --identity` took a hand-written file. The pilot's declared
`placement: { requestedGpuLayers: null, cpuOffloadEnabled: null, gpuConfirmed:
null }` for a deployment running `--n-gpu-layers 999 --cpu-moe` on a confirmed
device. Nothing was false; nobody had filled it in, and the evidence could not
say where the model ran.

It is read out of Bokahli's attestation now, beside the records, in the same run
that produced them. Three things it will not invent: `observedGpuLayers` stays
null rather than being set equal to the request; `enforcementConfirmed` is null
under the unconstrained regime even though the instance is capable; and
`reasoningMode` comes from the runtime's argv rather than from
`reasoningFormat`, which reports `"deepseek"` on a deployment started with
`--reasoning off`.

## Completions are kept

A structured-output verdict is a claim about specific bytes, and the previous
campaign kept none of them — which is how a mislabelled attempt survived a whole
campaign unreviewed. Each record carries the completion's digest; the bytes go
to `<out>.completions.json` in the gitignored run directory, verbatim, and never
into an export bundle.

refuses to pool them. The earlier unconstrained results are kept as they were

produced under 1.2.0.
